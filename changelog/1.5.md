A Dictionary, E-Ink keys, fonts you draw yourself, and sentence models for every language, so autocorrect reads the whole sentence.

## New

- **Dictionary.** Tools → Dictionary adds a word lookup to the keyboard. Open it and it defines the word you were just typing (or the one you've selected) without leaving the field: the senses it has, what part of speech each one is, and an example sentence. Tap the magnifying glass and the keys come back so you can type any other word. Every entry carries synonyms as tappable chips — tap one while the word you looked up is still under the cursor and it takes that word's place, keeping its capitalization, so finding a better word and using it is one tap. Words you've looked up stay as chips on the panel's landing screen. Definitions are written on device by Apple Intelligence, so nothing you look up leaves the phone and no Full Access is needed; on a phone that can't run it, the panel says which part is missing rather than disappearing.
- **E-Ink keys.** Customize → Looks → Design → Style has a new **E-Ink** material: an electronic-paper panel instead of plastic, glass or metal. Whatever colours the theme carries are pulled onto paper — never pure white, never pure black, snapped to the handful of greys a real panel holds — so a red theme becomes warm paper and a blue one cool paper rather than red or blue keys, and the board becomes the sheet the keys are printed on. Every cap carries the particle bed and pixel grid of a panel mid-refresh, a bold ink frame instead of a bevel, and letters printed in the same single pigment, because that is all a panel has — but the pigment takes its hue from the theme's own text colour, the way a colour panel filters the ink it already has, so a blue theme prints blue letters, frames and suggestions in a muted, paper-dark version of that blue rather than in flat black. Whatever colour is asked for, the pigment stays at one readable density. No gloss, no shadow, no press animation: a held key floods to solid ink the way e-paper repaints. It works with every key shape, per-key paint, font and layout, and travels with the theme through files and QR codes.
- **Draw your own font.** Customize → Looks → Design → Typography → Library now has a **Create** tile beside Import. Name a font, start it blank or from any face you already have — a built-in design, something you downloaded, something you imported — and draw the letters. Each character opens a canvas: draw it with a finger or Apple Pencil (pressure thickens the stroke), rub bits out with the eraser, and a Smooth slider decides how much of your own hand's wobble survives the trace. Switch to Points and the same letter is an editable outline — drag a node, pull its curve handles, add or delete points, turn a corner into a curve. Select adds flip, rotate, resize, centre and fit, plus box, round and bar shapes to build from. Copy a glyph and paste it into another (your O into your 0, then change it). Spacing is two margins, not typography jargon, and a letter can just follow the rest of the font. The keyboard you are making it for is pinned above the whole thing in your current theme, so changing the A changes the A on the key. Save and the font lands in the same picker as every other one — pick it and the keyboard uses it. Created fonts can be renamed, edited, duplicated and deleted from the picker; editing one reopens it with every outline and every stroke intact. Fonts you make are never attached to a theme you share. A font you drew from scratch can be exported as a .ttf to install elsewhere or send on; one you started from an existing face can't, because its letters began as someone else's work — the creator says so where the button would be.
- **Record my taps.** Customize → Keys → Hit Map has an opt-in switch that keeps where each tap of a word landed together with the word the keyboard committed and whether you kept it or backspaced it away — on this device only, never in a password field, with Export (share sheet) and Clear beside it. Off by default. Tap correction has so far been tuned on simulated fingers; real ones are what it needs next.
- **Sentence models for every language.** Languages → Language Mode (with more than one language active) can also load your other languages' on-device sentence models, so a word in your second language is judged by its own model rather than by none. Off by default; about 5 MB of memory per extra language.
- **Record my swipes.** Customize → Gestures → Swipe typing has an opt-in switch that keeps each glide's path together with the word you ended up with — the word the keyboard chose, the alternate you tapped instead, or nothing if you deleted it — on this device only, never in a password field, with Export (share sheet) and Clear beside it. Off by default. The swipe decoder has so far been tuned on synthetic strokes; real ones are what tuning it further needs.

## Improved

- **The one-handed shortcut turns it off again.** The hand icon in the suggestion bar only ever switched one-handed mode on; leaving it meant reaching for the gutter button or Customize. It now toggles, and shows the expand icon while one-handed mode is on.

## Fixed

- **Panel buttons easier to hit.** The back, save, clear and keyboard buttons in the header of every tool panel (Clipboard, Notepad, Calculator, Translate, and the rest) now sit in a row at least 44 pt tall instead of the 38 pt compact bar height, so a tap that lands a little high or low still counts. The suggestion bar itself keeps whatever height you set.
- **Conversion works on what you typed.** The Conversion tool now opens on the measurement under your cursor (or the one you selected) instead of a fixed example, shows the converted value large, and offers every unit of the same kind as full-width chips — no more dropdown menus with a hit target the width of two letters. Replace swaps the typed value for the result, Insert appends it, and Copy puts it on the clipboard. With nothing convertible under the cursor the panel says what to type and can read the clipboard instead. Suggestion-bar conversions now cover weight and volume as well as length (5kg → 11.02lb, 2L → 0.5283gal), pick the natural counterpart unit instead of always inches, and round to four significant digits. Temperatures convert too: 20c or 20°C → 68°F, 98.6f → 37°C.
- **The first swipe no longer freezes the keyboard.** A glide lifted before the swipe vocabulary and its shape index had finished building (the first swipe after the keyboard opened, sometimes) waited for them on the thread that draws the keys — up to four seconds, then rebuilt the whole dictionary there — so the word landed ten seconds late with the keyboard dead in between. The lifted word now waits off the keys' thread and lands the moment the build finishes; if you type on before that, it is dropped rather than inserted into what you typed.
- **The sentence rule fires a little more often, priced on data the model has never seen.** The bar for rewriting a common word on the sentence's evidence was set on sentences the model had been trained on. It has now been set again on a fresh Tatoeba export restricted to sentences newer than the training data: on those, a slightly lower bar still rewrites no correctly typed common word in either half, and repairs a quarter more of the corrupted ones. Rare words are still never touched by this rule.
- **A silent correction you keep teaches the keyboard where your fingers miss.** When a same-length correction stands (you type on without undoing it), each tap it corrected is recorded against the key you meant, so the learned per-key clouds finally include the slips that registered as another key — the part the ordinary landing statistics can never see. Same opt-in as Hit Map learning; nothing leaves the device.
- **A wrong word the whole sentence can see is corrected — and only then.** "There", "then", "from" and their kind are ordinary words, so no amount of frequency or one previous word can tell them from the word you meant, and the keyboard rightly left them alone. Now, once two or more words of the sentence are in, the on-device model reads the sentence as a whole; when it finds a one-edit neighbour of the word you just typed at least ten thousand times likelier there, and the corpus does not contradict it, it makes the swap, reversibly from the strip. The bar was set on a frozen eight-language corpus so that no correctly typed common word is rewritten in either half of it; that leaves some "then/than" slips unfixed on purpose, because a slightly lower bar rewrote "I could not here" to "have". Rarer words are never touched by this rule.
- **The next-word suggestions read the sentence.** With a neural model loaded, the top of the bar's next-word list is re-ordered by the model's probability of each whole word given everything typed so far. On the everyday English test set the first suggestion is right for 36 of 228 word boundaries instead of 30, and one of the three offered 51 times instead of 42.
- **Learned tap clouds no longer wreck correction when your hand moves.** The per-user landing statistics (Clink Form) were being turned into tap clouds so tight that any neighbouring key counted as a full miss; on simulated typing, a hand that drifted from its usual bias lost two thirds of its silent repairs. Clouds now keep only what the statistics really measure — where your taps centre — and the correction search reads those clouds too.
- **Autocorrect reads where your fingers landed, not just which keys registered.** A word typed with the whole hand a little off its keys, or drifting across the word, used to register as five wrong letters and stay that way: "jrllp" for "hello" was five edits from anything and no search reached it. The keyboard already records where each tap landed; correction now reads those landings against the dictionary directly, so a word whose taps sat near h-e-l-l-o is offered and, when the evidence is clear, committed — and a word whose taps sat squarely on j-r-l-l-p is left alone, because the landings are the evidence, not the letters. Run-together phrases with skipped letters ("howaryu") are read the same way and offered as phrases. Nothing changes for pasted text, hardware keyboards or words with no landing record. On simulated hand-offset typing the silent repair rate roughly doubled in five languages with damage unchanged or lower; the full text-only regression suite is byte-identical.
- **Accents restored where the sentence says so.** Croatian "covjek", Dutch "ben geinteresseerd" and their like were left bare because people type them bare often enough for the corpus to record it; when the previous word has been seen with the accented spelling and never with the bare one, the smaller frequency gap is enough. German ß was never restored at all — "straße" was being compared equal to "strasse" and thrown away — and now is, with the same sentence corroboration required, so Swiss "weiss" is left alone.
- **A real-word repair the resolver had already justified is no longer vetoed at the door.** Lithuanian "viskas geria" → "gerai" and English "away form" → "from" pass one evidence rule at both ends now, with the replacement required to be a strong collocation of the previous word.
- **Multi-word swipe is off by default** (and after Reset all settings). One glide reads as one word unless you turn it on under Gestures → Swipe typing; the setting you already chose is kept.
- **No more long pause on the first swipe after the keyboard opens.** The swipe vocabulary is built in the background when the keyboard appears, and a swipe that lifted before it was ready used to throw that work away and rebuild everything on the spot, freezing the keyboard for a second or more. The built vocabulary is now kept on the device between launches and loads in a few milliseconds, and a swipe that does arrive during a build waits for it instead of restarting it.
- **Swiping a key past the end of a word no longer changes the word.** Lifting on the key just past the last letter ("hey" ending on u, "are" ending on w) or landing on the key just before the first ("you" starting on t) used to hand the swipe to whatever word ends or starts there. The whole-word shape check now tries the word with its ends overrun by up to a key, so "heu", "atw" and "thou" stop appearing for words you clearly drew. On the held-out test set, swipes that overrun a whole key went from 81% to 94% right first time; the other conditions give up at most a word in three hundred.
- **Two-thumb swiping and phrases glided through the space bar are more accurate.** The whole-word shape check that rescues a heavily cut single glide sat out any word drawn by two thumbs and any word cut at the space bar. It now judges each gliding finger against its own letters (so "lovers" as v→e→r→s under one thumb and l→o under the other no longer reads as "loves"), and for a word that ran on into the space bar it compares the word part and the run down to the bar separately, so a missing or extra last letter is no longer hidden by the leg. A second thumb that starts its half of the word early or late is also no longer punished into splitting the word. On the held-out test set: phrases glided through the space bar 91% → 94% exact, two thumbs 97.0% → 98.7% when the thumbs move in letter order and 70% → 81% when they do not; single-finger swiping is unchanged.
- **Swipe typing reads the word you drew.** Gliding "typing" came out as "topping"; swiping "hey there how are" in a hurry came out as "Hey there hope artw". Several things behind that. The corner you turn on a key looked exactly like a deliberate pause, so the keyboard was free to double the letter. A word's ordinary frequency counted for far too little against the shape of the path, in exactly the cases where the path cannot tell two words apart. Corners are now read much more generously in both directions a finger misses one: cutting inside the key you meant, and — new — sailing straight past it and turning late, which is what turned "how" into "hope" and "are" into "artw". And an unfinished reading like "artw" can no longer take the place of a real word unless it is a decisively better fit, so half-words stop landing in your text. Across the held-out test set, words swiped with heavy corner-cutting went from 54% to 62% right first time, hurried sloppy swipes from 74% to 80%, heavily late turns from 92% to 94%, whole phrases glided through the space bar from 84% to 91% exact, and a single word wrongly broken into two happens roughly half as often. Two thumbs gliding at once is a little less accurate than it was (99% to 97%) — the wider tolerance that reads a hurried finger correctly is a poorer fit for two short half-strokes.
- **The first swipe after opening the keyboard is no longer slow.** Part of what the swipe decoder needs — a map of the whole vocabulary onto the current key layout — was built the first time you swiped, on the same thread that draws the keyboard, so the first word of a session appeared late. It is now built in the background the moment a glide starts, while your finger is still moving, and the word lands as fast as every later one.
- **Learned words keep their own capitalization.** A word the keyboard had watched you type once with a capital — a slipped shift, a name in a list, anything — became capitalized for good, and every later use of it was quietly rewritten: "not" turned into "Not" in the middle of a sentence for no reason you could see. A capital now has to earn the spelling. It counts only where you actually chose it (never a sentence opening, caps lock or a field that capitalizes every word), it has to appear at least twice, it has to keep outweighing the times you write the same word in lowercase, and it drops away on its own when it stops. Distinctive spellings like "iPhone" or "SwiftKey" are unaffected — no sentence start can produce those — and tapping a name in the suggestion bar still teaches it in one go, because that is you choosing the spelling rather than the keyboard guessing it. A word you type and then delete no longer votes at all.
- **The suggestion bar shows the word it is going to type.** At the start of a sentence the bar offered "nothing" and then inserted "Nothing"; the same gap opened in fields that capitalize every word and while shift was held. Every chip — completions, corrections and the top pick — is now shown in exactly the capitalization the tap will commit.
- **An imported font now appears straight away.** Importing a font — or downloading one from a repository — registered the file at its temporary location and then moved it into place, leaving the system holding a font whose file was no longer there. The face looked installed, the preview stayed on the old one, and only reopening Clink fixed it. Fonts are now put in place first and registered second, and a font being replaced or rebuilt is unregistered before its old file goes, so re-importing and re-saving work the first time too.
- **The swipe trail is a smooth stroke again, not a string of beads.** Styled trails — neon, sparkle, comet, rainbow, fire, ocean — and any trail with a fading tail or a width that tapers were painted in pieces, and the round ends of neighbouring pieces stacked up at every join into a darker dot. The pieces now composite as one stroke, so the colour, the fade and the taper stay exactly as chosen with no beading. A trail whose look never changes along its length is drawn in a single pass, and a uniform width other than the default is no longer ignored.
